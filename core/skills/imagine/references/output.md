# Context lake

## Layout

```text
~/.agents/imagine/<slug>/          # or the --out path
├── README.md          # index of the lake (below)
├── findings.md        # the findings document (template below)
├── brief.md           # verbatim original brief + settled decisions + open items
├── persona.md         # role card (references/roles.md)
├── research.md        # references, successes, failures, market, with source marks
├── sources.md         # every source: URL, access date, status
├── canon.json         # fixed axes (references/canon-and-registry.md)
├── steps.md           # creation steps → sub-steps → goals, actors, validating case
├── risks.md           # challenges and opportunities with plans; failures to prevent; successes to match
├── story.md           # full story; entities as [[id]]
├── registry.json      # entity tables (source of truth)
├── registry.md        # rendered tables (registry.py render)
├── plan.md            # plan built around the story
├── run-log.md         # waves, decisions, stop reason, reviewer verdicts, design proposals
├── design.json        # art direction owned by imagine (P9)
├── assets/            # written only by the imagine-design child (its SKILL.md has the layout)
└── expansions/        # <target-id>.json + <target-id>.md per expansion child
```

## `README.md`

```markdown
# <Title>

<One-line brief.> Generated by `imagine` on <YYYY-MM-DD> as <persona role>.

| File | What it holds |
|---|---|
| [findings.md](findings.md) | Start here: the full findings document |
| [story.md](story.md) | The story |
| [plan.md](plan.md) | Plan built around the story |
| … one row per file present … |

Counts: <N> entities, <N> links, <N> waves, <N> expansion children, <V> verified / <U> unverified claims, <P> assets passed / <F> failed.
Stop reason: <saturation | ceiling>.
```

## `findings.md` template

Sections in this order. Cite registry entities as `[[id]]` only in `story.md` and `steps.md`; elsewhere use names.

```markdown
# <Title>: findings

## Brief and persona
## Research
### References (modern and classical)
### Successes
### Failures
### Market (hype versus trend, niche versus broad, market versus money waste)
## Canon
## Creation steps
<step → sub-steps → goal; actors; the real case that validates it>
## Challenges and opportunities
<each with a plan; failures to prevent; successes to match and how to surpass them>
## Story
## Characters and places
<short summary; full tables in registry.md>
## Plan around the story
## Art direction and assets
<design.json in prose; asset counts from assets/manifest.json; accepted and rejected proposals; omit the assets part when none were made>
## Pros and cons
## Open assumptions
## Claims
Verified: <V>. Unverified: <U>.
```

Each research item ends with `([source](url), accessed YYYY-MM-DD)` or `(unverified)`.

## Game section set

A game brief adds these sections after "Characters and places", each with pros and cons:

- Scenarios
- Mechanics (core loop, progression, economy)
- Characters (playable and non-playable)
- Skills
- Graphics (style, references, budget)
- Maps
- Quests
