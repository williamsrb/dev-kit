When the user wants **multiple PRD tasks on the same repo at once** (same Epic/Release or local slugs; parallel worktrees, several PRD→plan→impl flows), read and follow the `multitask-same-repo` skill before any setup. It holds the hard constraints: `git worktree` isolation, sharing only via disk, a fresh session per phase, shared work once before fan-out, one implementer per worktree. `mult` does **not** activate it (`mult` = `orchestrate`). Single task: ignore this.
